## HEVC Alpha 实测

`npm run setup:hevc-alpha` 已完成 NASM、pkgconf、启用 Alpha 的 x265 4.2 和 FFmpeg 8.1 构建；安装结束的 RGBA 往返检测通过。0%、50%、100%、25% 不透明度样本分别解码为 Alpha **0 / 129 / 255 / 64**，颜色在量化误差内正确。再次运行安装命令复用已验证编码器。

在独立临时后端，设置 `TRACE_REQUIRE_HEVC_ALPHA=1` 后，`test:e2e` 和 `test:e2e:subpath` 均通过。HEVC 输出为单条 `hevc` / `hvc1` 视频流的 MOV，25 帧全部实际解码；透明背景、50% 路线、直通颜色正确。运行中 HEVC 编码能从第 0 帧推进，并能取消，随后浏览器导出仍成功。未安装能力的模拟环境明确禁用导出并显示安装说明；改选 ProRes 后可正常导出。

西湖示例截取前 240 秒，120× / 320 × 320 / 12 FPS / 25 帧，关闭辉光与起终点、路线不透明度 50%、线宽 10 px：

| 输出 | 背景不透明度 | 大小 |
| --- | --- | --- |
| ProRes 4444 MOV | 35% | 1,204,720 字节 |
| HEVC Alpha MOV | 35% | 18,683 字节 |
| HEVC Alpha MOV | 0% | 23,635 字节 |

相同 35% 背景场景，HEVC Alpha 约为 ProRes 的 **1/64.5**。两者背景 Alpha 均约 89，背景颜色正确；这是该固定镜头样本的实测比例，不是所有轨迹的压缩保证。

还实际导出了完整默认示例：极简透明背景、默认颜色 / 辉光 / 起终点、60× / 640 × 640 / 30 FPS，**5,231 帧、174.366667 秒、2,713,392 字节**，本机完成用时约 **43 秒**。全部 5,231 帧逐帧解码，背景 Alpha 正确，帧数、时长与单流 `hvc1` 标识正确。成品为 `test-results/default-hevc-alpha.mov`，短片为 `export-hevc-alpha.mov` 与 `export-hevc-alpha-semi.mov`。

Apple 播放器、Final Cut Pro、Premiere 等未实测。部分旧解码器只读颜色层；HEVC 是有损格式，Alpha 边缘会有量化误差，不能替代所有高质量 ProRes 工作流。

针对后续报告的粗线 / 光晕问题，使用同一实际导出的 640 × 640 MOV 对照：FFmpeg 8.1 解码的 Alpha 范围为 0–255，仅 116 个像素完全不透明；旧解码器输出全部 409,600 个像素 Alpha 为 255。只显示颜色层时，细线变粗带、标记光晕变实色；正确合成 Alpha 后正常。比较图为 `test-results/hevc-quality/player-comparison.png`，左侧读取 Alpha，右侧忽略 Alpha。另生成前 5 秒的不透明 H.264 合成预览 `composited-preview.mp4`，用于通用播放器核对。

独立 1 / 2 / 4 / 8 px 细线样本在原 CRF 18 设置下，其半透明阈值线宽全部保持不变；代表性截面的 Alpha 最大误差为 1–2。提高质量并不能修复忽略 Alpha 的播放端。新增 `tests/hevc-quality.test.mjs` 通过真实渲染脚本编码两帧带辉光和移动标记的几何轨迹，要求可见面积、Alpha 总量与源帧差异小于 6%，平均 Alpha 误差小于 0.5，黑 / 灰 / 白背景的 RGB 平均合成误差小于 1；忽略 Alpha 的反例可见面积至少放大三倍。

实际视频与界面截图位于 `test-results/`。旧合成 KML 和 COROS 活动 KML 已移除；COROS 解析兼容性由合成分段和 Lap 数据验证。

## 部署检查与边界

`docker compose config --quiet` 通过。更名前已实际构建 `trace-studio:hevc-alpha` 镜像（当前构建示例使用 `pudding-track-studio`），并在随机本地端口启动临时容器：健康检查识别独立 HEVC Alpha 编码器，API 实际导出 320 × 320 / 12 FPS / 25 帧半透明 MOV，大小 18,607 字节。使用容器内 FFmpeg 8.1 解码全部帧，背景 Alpha 约 89、颜色正确；ffprobe 确认只有一个 `hevc` / `hvc1` 流，下载 MIME 为 `video/quicktime`。验证结束后清理临时容器，没有占用现有 8000 端口或挂载用户数据。

此环境 Docker Desktop 无法通过容器的 `127.0.0.1:7897` 访问宿主代理，改用构建参数 `HTTP_PROXY` / `HTTPS_PROXY=http://host.docker.internal:7897`；Debian 官方源在代理下较慢，构建时使用 `DEBIAN_MIRROR=https://mirrors.tuna.tsinghua.edu.cn`。默认 Dockerfile 仍使用官方源，源码版本及 SHA-256 保持固定。构建日志位于 `test-results/docker-hevc-build.log`。

预览 / 导出复用绘图代码，但两种 Canvas 实现的字体和抗锯齿可能略有不同。VP9 alpha 在部分剪辑软件中支持有限，ProRes MOV 是另一个可选输出；编码与 alpha 的验证已包含实际解码，而非仅检查后缀或容器标签。
